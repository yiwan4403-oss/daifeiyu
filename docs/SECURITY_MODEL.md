# SECURITY_MODEL — Resident 安全模型

日期：2026-11-06 ｜ 原则：安全由程序执行，不由 LLM 自觉。

## 权限等级（L0–L3）

| 级 | 允许 | 典型操作 |
| --- | --- | --- |
| L0 | 只读、思考、规划 | 读自己的记忆/配置、生成计划 |
| L1 | 受限工作区内创建文件与测试 | 写 workspace/sandbox、跑 pytest |
| L2 | 授权的部署、依赖安装、外部操作 | 安装插件、发消息到已授权平台 |
| L3 | 人工确认 | 改核心身份/记忆策略/安全系统/Core、删除重要数据、支付、提权 |

- 权限绑定「资源 + 动作」，不是给人发令牌。
- **模型不得批准自己的权限申请**（审批永远由程序或人完成）。

## 默认自动放行（总纲 9.1，需配置确认）

读公开网页、搜 GitHub、读文档、建工作区文件、写代码、跑允许的测试、
整理自己的记忆、生成计划、更新非关键内部状态。

## 默认需授权（9.2）

装新依赖、装新插件、用新账号、向外部平台发消息、公开发布、
改非核心运行配置、有外部影响的自动化。

## 永远需人工确认（9.3）

删重要数据、改核心身份/记忆存储策略、改权限/安全系统、改 Core、
支付转账、授予管理员权限、对外公开重要个人信息。

## 授权黑名单（借 PaulusAI）

`rm -rf`、`curl | sh`、`sudo`、`sh -c`、任意提权与裸网络下载执行 → 永不可授权。

## 不可信数据边界（总纲 9.4）

- 网页 / GitHub / MCP 工具返回内容一律 `untrusted`，不得升格为系统指令。
- 提示注入：外部文本中的“指令”只当数据处理。
- 模型生成代码：先测试 → 人工审 → 才可进生产目录。
- 密钥：不进代码库、不进日志；用环境变量/Secret Manager。

## 审计与回滚

- 所有 L1+ 操作写 audit 表（谁/何时/什么/结果）。
- 备份自动执行 + 定期恢复演练（总纲 13.7：备份要能实际验证恢复）。
- 每次部署前 snapshot；回滚命令写进 README。

## 人格自改边界（总纲 13.8）

| 内容 | 是否可自改 |
| --- | --- |
| 兴趣 / 偏好 | 允许渐变 |
| 情绪 | 自然变化 |
| 观点 | 依证据修正 |
| 技能 | 允许学习 |
| 基础性格 | 有限变化，留历史 |
| 核心身份 | 严格保护（L3） |
| 安全边界 | **不得自行修改** |
